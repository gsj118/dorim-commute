# HCI Chapter 06 작업분석·어피니티 다이어그램 — 최종 제출본 제작 및 종합 검증

## 1. 역할 및 최종 목표

당신은 대학 HCI(Human–Computer Interaction) 과목의 전문 교수, UX 리서처, 작업분석(HTA) 전문가, 어피니티 다이어그램 분석가이자 학술 과제 품질 검증자입니다.

첨부된 교수자 강의자료, Chapter 06 워크북, 이전 Chapter 02~05 제출본, 공식 통학버스 운행노선표, Unibus 화면 자료를 정밀하게 분석하여 Chapter 06 「작업분석과 어피니티 다이어그램」의 완성도 높은 제출용 결과물을 제작하세요.

이번 과제는 다음 프로젝트의 연속 과정입니다.

프로젝트명: 목포대학교 광주권 통학생을 위한 생활권 장소 기반 등하교 통학버스 이용정보 탐색 UI 개선

작성자: 구서준 / 학번: [학번 가림]  
수업: Human Computer Interface  
수행 방식: 1인 프로젝트

최종 목표는 다음과 같습니다.

1. 기존 사용자 경험과 자료를 분석 가능한 원자 메모로 구조화합니다.
2. 상향식 어피니티 다이어그램을 통해 사용자 행동의 의미와 패턴을 분석합니다.
3. 인사이트와 반대 사례를 도출합니다.
4. 등교·하교 과업의 계층적 작업분석(HTA)을 수행합니다.
5. 현재 작업 흐름(As-is)과 잠정 개선 흐름(To-be)을 비교합니다.
6. 근거에 기반한 사용자 요구사항과 설계 우선순위를 도출합니다.
7. 교수자가 지정한 생성형 AI 활용 실습을 수행하고 인간의 검토와 AI 분석을 구분합니다.
8. Chapter 07의 아이디어 도출 및 페르소나 작성에 연결 가능한 분석 결과를 확보합니다.
9. 원본 워크북에 맞춘 최종 제출 문서와 필요한 시각자료를 제작합니다.

최우선 평가 기준은 자료의 진실성, 교수자 요구사항 충족, 분석의 논리성, 근거 추적성, 이전 과제와의 일관성입니다.

분량이나 형식적인 완성도를 높이기 위해 사실을 만들어서는 안 됩니다.

## 3. 필수 연구 원칙

### 3.1. 실제 조사 범위 준수

Chapter 05는 작성자 본인 U01의 통학 경험 회고와 해석 확인, 기존 화면·공식 운행자료 분석을 중심으로 작성되었습니다.

별도 참여자의 실제 과업 관찰이나 현장 맥락질의가 완료되었다는 근거는 없습니다.

따라서 다음을 엄격히 금지합니다.

- 존재하지 않는 참여자·인터뷰·관찰·발화 생성
- 회고를 현장 직접 관찰로 표현
- 여러 사건을 하나의 연속 관찰 기록으로 조합
- 서로 다른 기록 ID를 독립적인 사용자 수로 해석
- 실제 측정하지 않은 성공률·소요시간·빈도 생성
- 사용자 1명의 행동을 전체 통학생에게 일반화
- AI가 만든 군집을 사람이 직접 작성한 것으로 표현
- 검증되지 않은 개선 효과를 실제 성과로 서술

모든 핵심 결과에서 다음 유형을 구분하세요.

실제 경험 진술 / 문서·화면 사실 / 분석적 해석 / 설계 가설 / 추가 검증 필요

### 3.2. 긍정 및 반대 근거의 균형

장소 기반 검색은 프로젝트의 초기 해결 가설일 뿐, 사용자 연구로 효과가 확정된 기능이 아닙니다.

현재 Unibus 기능이 도움이 되는 사례와 익숙한 통학생이 별도 확인 없이 이용하는 사례도 반드시 분석하세요.

특정 해결안을 정당화하기 위해 불리한 근거를 배제하지 마세요.

## 4. STEP 1 — 원자료 분절 및 원자 메모 작성

Chapter 05의 원자료를 분석하여 M01~Mn 형식의 어피니티 메모를 작성하세요.

원본 워크북은 메모 20개 이상을 입력 조건으로 제시합니다.

그러나 실제 근거가 충분하지 않으면 개수를 맞추기 위해 자료를 조작하지 마세요.

### 작업 절차

1. R/E/T/Q/C/I/O의 원천과 상호 관계를 확인합니다.
2. C/I/O 등 분석 결과를 원래 경험·화면·문서 자료로 역추적합니다.
3. 독립적인 의미 단위로 메모를 분절합니다.
4. 메모마다 하나의 행동·발화·사실을 기록합니다.
5. 동일 경험의 중복 진술은 별개의 독립 사건으로 계산하지 않습니다.
6. 실제 사용자 경험과 문서 기반 분석 메모를 분리합니다.
7. 정당하게 추출 가능한 메모 수를 산정합니다.

### 필수 메모 항목

- 메모 ID
- 자료 주체 또는 출처
- 행동·발화·사실
- 상황
- 등교/하교/공통
- 원자료 ID
- 자료 유형
- 근거의 한계

원자료 문장을 임의로 수정하거나 의미를 변경하지 마세요.

직접 인용은 실제 제공된 문구만 사용하고, 정리된 설명은 진술 요약으로 표시하세요.

20개 미만이 정당하게 추출된다면 실제 개수를 유지하고 추가 조사가 필요한 이유를 명시하세요.

메모 20개 확보보다 근거의 정직성과 추적 가능성을 우선합니다.

## 5. STEP 2 — 어피니티 다이어그램 및 AI 대안 군집 비교

교수자 강의자료의 상향식 어피니티 분석 원칙을 적용하세요.

### 5.1. 기본 군집화

다음 과정을 수행합니다.

1. 모든 원자 메모 검토
2. 메모의 행동·맥락·의미 파악
3. 의미가 가까운 메모의 잠정 그룹 구성
4. 그룹 간 관계 재검토
5. 군집 분리·병합·재배치
6. 사용자 행동 패턴을 설명하는 제목 작성
7. 상위 주제와 반대·미분류 메모 정리

처음부터 장소 검색, 지도, 정류장 등 기존 기능 범주에 메모를 끼워 맞추지 마세요.

군집 제목은 다음과 같은 사용자 행동 패턴 문장으로 작성하세요.

`사용자는 ___할 때 ___한다.`

워크북의 G01~G05 구조를 기본으로 삼되 실제 자료의 특성에 따라 필요한 개수로 조정하세요.

### 5.2. 교수자 지정 AI 활용 실습

동일한 원자 메모를 사용하여 실질적으로 다른 AI 군집안 A와 B를 반드시 생성하세요.

두 군집안 모두 다음을 만족해야 합니다.

- 원본 메모 ID 보존
- 메모 문장과 의미 보존
- 서로 다른 실질적인 군집 기준
- 사용자 행동 중심 군집 제목
- 군집별 포함 메모 명시
- 반대 사례 및 미분류 메모 보존
- 각 군집의 판단 근거 제시

두 군집안은 단순히 명칭만 변경한 결과여서는 안 됩니다.

### 5.3. 사람의 1차 군집 처리

교수자는 사람이 먼저 1차 군집을 만들고 AI 결과와 비교하도록 요구합니다.

첨부 자료에 실제 작성자가 직접 만든 1차 군집이 존재하는지 확인하세요.

존재한다면

- 사람의 원본 군집을 그대로 보존합니다.
- AI 군집안 A·B와 비교합니다.
- 공통점·차이점·누락·과도한 통합을 분석합니다.

존재하지 않는다면

- 사람이 작성한 군집을 임의로 생성하지 않습니다.
- AI 군집안 A·B를 완성합니다.
- 작성자가 직접 군집화할 수 있도록 원자 메모 목록과 빈 군집 작성 양식을 제공합니다.
- 사람의 1차 군집과 AI 비교는 '작성자 직접 수행 필요'로 표시합니다.
- 사람의 최종 승인이나 수정을 완료한 것으로 기록하지 않습니다.

### 5.4. 군집 결과 비교

다음 기준으로 비교표를 작성하세요.

- 군집 기준의 차이
- 메모 누락 여부
- 과도한 통합·분할 여부
- 반대 사례 처리
- 사용자 목표와 행동 설명력
- 근거 추적성
- 후속 설계 활용성

AI 관점에서 더 적절하다고 판단한 잠정 군집안과 근거를 제시하되, 사람의 최종 선택과 구분하세요.

### 5.5. 시각화

메모 ID와 군집 구조를 이해할 수 있는 어피니티 다이어그램을 제작하세요.

가능하다면 별도의 SVG 또는 적절한 시각자료로 제공하고, Markdown 문서에서도 구조를 확인할 수 있도록 하세요.

시각적 완성도보다 군집의 정확성과 추적성을 우선합니다.

어피니티 분석에서 도출한 사용자 행동 패턴을 바탕으로 핵심 인사이트 3개를 작성하세요.

- 관련 메모 ID
- 관련 군집 ID
- 원자료 ID
- 근거가 되는 사용자 행동·경험
- 분석자의 해석
- 반대 사례 및 예외
- 확신도 1~3
- 확신도 판단 근거
- 설계적 의미
- 후속 확인 질문

### 반드시 고려할 경험

Chapter 05에는 다음과 같은 중요 사례가 있습니다.

- 익숙한 통학에서는 별도의 정보 재확인을 하지 않는 경우
- 새 학기 또는 낯선 장소에서 추가 정보를 확인하는 경우
- 등교와 하교의 실제 승하차 위치가 다른 경우
- 외부 지도를 사용해 목적지와 통학버스 지점의 가까운 정도를 직접 대조한 경우
- 기존 Unibus 지도가 개별 정류장 위치 확인에 도움이 되는 경우

단, 위 사례를 미리 고정된 군집이나 인사이트로 사용하지 마세요.

실제 메모 분석에서 해당 의미가 어떻게 연결되는지 검토한 후 판단하세요.

### 반대 사례 탐색 실습

각 인사이트에 대해 다음을 별도로 수행하세요.

1. 인사이트를 반박하거나 다른 해석을 허용하는 메모 탐색
2. 반대 사례의 메모 ID 기록
3. 인사이트와의 충돌 이유 분석
4. 인사이트 유지·수정·보류 판단
5. 추가 확인이 필요한 질문 작성

반대 사례가 발견되지 않더라도 인사이트가 입증되었다고 단정하지 마세요.

자료 부족과 반대 근거 부재를 구분하세요.

## 7. STEP 4 — 계층적 작업분석(HTA)

교수자 강의자료의 목표–과업–행동 구분과 HTA 작성 원칙을 적용하세요.

### 분석 대상

등교 목표

광주의 출발 장소에서 도림캠퍼스로 이동하기 위해 적절한 승차지점, 운행편, 승차 시각, 실제 위치와 운행 조건을 확인합니다.

하교 목표

도림캠퍼스에서 광주의 목적지로 이동하기 위해 적절한 하차지점, 경유 운행편, 학교 승차 위치, 학교 출발 시각과 운행 조건을 확인합니다.

### 필수 작성 결과

1. 대표 과업의 최종 목표
2. 목표·하위 과업·행동 계층
3. 작업 번호 체계
4. 선행 조건
5. 필요한 정보 및 도구
6. 오류·예외
7. Plan 0 및 필요한 하위 Plan
8. 계층적 작업목록
9. HTA 다이어그램

등교와 하교의 공통 과업은 적절히 공유하되, 방향별로 다른 정보와 판단을 명확히 구분하세요.

특히 다음 사항을 반영하세요.

- 익숙한 통학과 새 정보 탐색의 조건부 분기
- 장소와 통학버스 지점의 관계 판단
- 후보 지점 비교
- 실제 승하차 위치 확인
- 운행 시각과 요일 조건 확인
- 정보가 부족할 때 추가 자료 확인
- 오류 또는 불확실성이 있을 때 재탐색

실제 확인되지 않은 작업 단계는 사용자 행동의 실측 사실이 아니라 분석용 모델의 가정으로 표시하세요.

### HTA 누락 점검 — 교수자 AI 활용 실습

HTA 초안 작성 후 독립적인 작업분석 검토자의 관점에서 다음을 점검하세요.

- 목표와 기능을 혼동하지 않았는가?
- 과업과 세부 행동의 추상화 수준이 적절한가?
- 선행 조건이 빠져 있지 않은가?
- Plan 순서가 실행 가능한가?
- 조건부 분기와 반복 흐름이 적절한가?
- 예외와 실패 상황을 충분히 고려했는가?
- 등교와 하교의 과업 차이를 정확히 반영했는가?
- 근거 없는 행동을 실제 관찰된 행동처럼 표현하지 않았는가?

발견한 문제는 다음 형식으로 기록하세요.

`문제점 → 관련 근거 → 수정안 → 수정 여부`

정당한 수정만 최종 HTA에 반영하세요.

이 검토는 AI의 자체 검토이며 사람이 직접 검토한 결과로 표현하지 마세요.

## 8. STEP 5 — As-is 작업 흐름

기존 Unibus, 공식 노선표 및 사용자의 실제 경험을 중심으로 현재 작업 흐름을 분석하세요.

반드시 다음 상황을 구분해야 합니다.

상황 A: 익숙한 통학

- 이미 알고 있는 노선과 승하차 위치 활용
- 별도의 재탐색 없이 이용하는 경우

상황 B: 추가 정보가 필요한 통학

- 새 학기 또는 낯선 장소
- 공지·노선표·Unibus 확인
- 필요에 따른 외부 지도 비교
- 사람이나 AI를 통한 추가 정보 확인 가능성

상황 B의 모든 도구를 한 번의 실제 연속 작업에서 사용한 것으로 표현하지 마세요.

또한 2025년 북구 목적지 탐색 경험은 독립적인 회고 사례로 취급하세요.

### As-is 작성 항목

- 단계
- 사용자 행동
- 필요한 정보·도구
- 시스템 반응
- 판단 또는 확인 과정
- 마찰·오류·불확실성
- 근거 ID

워크북의 기본 구조를 따르되, 등교·하교 분기나 익숙함에 따른 차이를 표현할 수 있도록 보완하세요.

가장 중요한 마찰 지점 2개를 도출하고 근거의 수준을 명시하세요.

서비스의 불편을 과장하지 말고 현재 기능이 효과적으로 작동하는 사례도 남기세요.

## 9. STEP 6 — To-be 작업 흐름

As-is와 인사이트에서 확인된 사용자 요구를 바탕으로 잠정 개선 작업 흐름을 구성하세요.

이전 과제의 '생활권 장소 기반 탐색'은 주요 후보로 검토하되 자동으로 최종 채택하지 마세요.

다음 대안도 함께 고려하세요.

- 기존 노선 목록 개선
- 정류장명 검색
- 지역별 필터
- 지도 중심 탐색
- 장소 기반 승하차지점 후보 탐색

이번 장의 주된 목적은 아이디어를 최종 확정하는 것이 아니라 사용자 작업이 어떤 방향으로 개선되어야 하는지 설명하는 것입니다.

### To-be 작성 항목

- 단계
- 개선 후 사용자 행동
- 시스템 지원·피드백
- 제거 또는 단순화되는 작업
- 남아 있는 작업
- 새롭게 발생하는 위험
- 관련 인사이트·근거 ID

As-is와 To-be를 비교하여 실제로 무엇이 달라지는지 사용자 행동 수준에서 설명하세요.

장소 검색 실패, 지원되지 않는 지역·운행편, 운행 조건 불확실성 등의 상황에서도 사용자가 기존 경로로 돌아갈 수 있도록 고려하세요.

To-be는 실제 구현된 결과가 아닌 설계 가설로 명시하세요.

## 10. STEP 7 — 사용자 요구사항과 우선순위

어피니티 군집, 인사이트, HTA 및 작업 흐름 분석을 바탕으로 사용자 요구사항을 최소 3개 도출하세요.

요구사항은 기능명이 아니라 사용자가 달성해야 하는 과업과 결과를 중심으로 표현하세요.

### 필수 항목

- 우선순위
- 사용자 요구사항
- 근거 원자료 ID
- 연결 메모·군집·인사이트
- 해당 과업
- 검증 지표
- 목표값
- 목표값의 성격
- 미검증 사항

### 우선순위 기준

1. 사용자 목표 기여도
2. 문제의 중요성
3. 근거의 충분성
4. 정확성 및 정보 오해 위험
5. 구현 가능성과 필요한 노력
6. 접근성 및 기존 사용자에 대한 영향

### 기존 목표 유지

Chapter 03의 잠정 목표를 정확히 유지하세요.

- 등교·하교 각각 올바른 이용정보 확인 성공률 90% 이상
- 정확하게 완료한 비교 가능한 과업의 완료시간 중앙값을 기존 방식 대비 30% 이상 감소

위 수치는 실제 측정 결과나 교수자 지정 수치가 아니라 기존 프로젝트에서 설정한 잠정 가상 설계 목표입니다.

현재 기준값과 개선 결과가 미측정임을 명확히 표시하세요.

새로운 정량 지표를 제안할 수 있으나 실측 결과처럼 표현하지 마세요.

최종적으로 다음 추적 관계를 확인할 수 있어야 합니다.

`원자료 → 원자 메모 → 어피니티 군집 → 인사이트 → 작업분석 → 사용자 요구사항 → 검증 지표`

## 11. 프로젝트 고정 조건과 정확성 관리

다음 조건을 준수하세요.

1. 대상은 광주권과 도림캠퍼스 사이의 등교·하교입니다.
2. 예약·탑승이력 개편은 대표 과업에서 제외합니다.
3. 차량위치조회는 기존 서비스 기능이지만 이번 개선의 핵심 범위가 아닙니다.
4. 기존 Unibus에는 노선 목록과 정류장 지도 기능이 있습니다.
5. 기존 화면에서 확인하지 못한 기능을 서비스 전체에 없다고 단정하지 않습니다.
6. 서광주우체국 등교 승차 위치는 '서광주우체국 건너편 CU편의점'입니다.
7. 서광주우체국 하교 하차 위치는 '서광주우체국 앞'입니다.
8. 등교 승차지점의 탑승 시각과 하교 시 학교 출발 시각을 혼동하지 않습니다.
9. 하교 노선을 등교 노선의 단순 역순으로 구성하지 않습니다.
10. 공식 자료에 없는 하차 시각·좌표·거리·도보시간을 생성하지 않습니다.
11. 공식 운행노선표의 '(안)' 표기와 자료 간 불일치를 고려합니다.
12. 최신 확인이 필요한 운행 조건은 미확정으로 표시합니다.
13. 실시간 도착 예측, AI 추천, 완성형 길찾기, 필수 위치 권한 및 정확한 집주소 수집은 제외 범위를 유지합니다.
14. 실제 사용자 평가와 웹 구현이 완료되었다고 기록하지 않습니다.
15. 연구 결과가 기존 개선 가설과 다르더라도 원자료의 의미를 우선합니다.

- 원자료 추적이 가능한가?
- 동일 경험을 반복 증거로 과장하지 않았는가?
- 실제 경험과 분석적 해석을 구분했는가?
- 반대 사례를 보존했는가?
- 기존 UI의 강점을 정당하게 반영했는가?
- 초기 해결 가설에 편향되지 않았는가?
- 자료의 한계를 적절히 기술했는가?

### 검토자 C: 프로젝트 품질 검증자

- Chapter 02~05와 모순되는 내용이 있는가?
- 등교·하교 범위가 누락되지 않았는가?
- 승하차 위치·시각·요일 조건이 정확한가?
- 실제로 수행하지 않은 활동을 완료 처리했는가?
- 다이어그램과 표의 ID가 정확히 연결되는가?
- 요구사항과 검증 지표가 측정 가능하게 작성되었는가?
- Chapter 07로 연결할 수 있는 분석 근거가 명확한가?

### 검토 결과 처리

발견한 문제는 다음 기준으로 처리하세요.

1. 근거로 확인 가능한 오류는 수정합니다.
2. 표현이 불명확한 부분은 정리합니다.
3. 자료가 부족한 부분은 한계와 후속 조사 계획을 명시합니다.
4. 추가 검증이 필요한 내용을 억지로 완성하지 않습니다.
5. 수정 후 원자료와 최종 문서를 다시 대조합니다.

AI 자체 검토는 실제 사람의 독립적인 검수로 표현하지 마세요.

사소한 형식 선택을 이유로 작업을 중단하거나 불필요한 확인 질문을 반복하지 마세요.

명확하지 않은 사항은 확인된 사실과 구별하여 표시하고, 제공된 자료 안에서 최대한 정확한 결과물을 완성하세요.
