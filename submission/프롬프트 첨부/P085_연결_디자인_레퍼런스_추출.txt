# 화정동 하교 결과의 디자인 시스템 초안


## 실행 프롬프트

목포대학교 광주권 통학버스 앱에서 화정동 하교 결과를 대표 화면으로 삼아 디자인 시스템 초안을 만들어줘. 이번 단계의 산출물은 측정 근거, 프로젝트용 `docs/design/DESIGN.md`, 실제 내용으로 만든 모바일 비교 시안이야. 앱에 적용하는 작업은 다음 단계로 두자.

1. **현재 화면을 기준으로 잡아줘.** AGENTS.md, 최근 UX_FLOW, 현재 PlaceSearch와 styles.css, `docs/evidence/progressive-lists-20261112/live/390-candidates.png`를 확인해. 390px에서 서광주우체국 카드의 지점명, 두 편의 출발 시각, 큰 상세 버튼의 반복, 긴 거리 기준 문장이 어떤 순서로 읽히는지 짚어줘.

2. **정보 배치 규칙은 이미 고른 두 자료에서 가져와.** GOV.UK Summary list(https://design-system.service.gov.uk/components/summary-list/)에서는 결과 목록의 항목명·값 정렬과 지점별 묶기를, SBB Pearl-Chain(https://digital.sbb.ch/en/design-system/lyne/components/pearl-chain/)에서는 상세 화면의 학교 승차→광주 하차 순서와 시각을 붙일 위치를 참고해. 각각 공식 문서가 연결하는 실제 예시를 찾아 Dembrandt로 추출해. 해당 요소의 간격·행 정렬·구분선을 중심으로 해석해줘.

3. **시각적 방향은 별도의 실제 서비스에서 골라줘.** 후보 두 곳을 찾아 모바일 화면을 나란히 비교해. 하나는 한글 지명과 숫자가 밀집한 국내 교통·지도·생활정보 서비스, 다른 하나는 서체·색·여백에서 다른 접근을 보여주는 서비스로 찾아줘. Awwwards 같은 갤러리에서 발견한 경우에는 출품작의 실제 서비스 화면으로 들어가. 각 후보의 정확한 URL, 참고할 화면, 화정동 카드에 가져올 규칙 한 가지와 포기할 요소 한 가지를 알려줘. 한글 지명·출발 시각의 가독성, 화면에 담기는 정보량, 선택·주의 상태의 구분을 근거로 **비주얼 기준 한 곳**을 선정해. 두 후보의 장식 요소를 전부 섞을 필요는 없어.

4. **선정한 비주얼 레퍼런스에도 Dembrandt를 실제 실행해.** 도구 버전과 지원 옵션을 확인하고, 앱 의존성과 분리해 실행해. 외부 추출 대상은 기본 세 곳(구조용 두 예시와 비주얼 기준 한 화면)이야. JSON 및 화면 캡처를 기존 근거 폴더 관례에 맞춰 보관하고 URL·화면 폭·대상 요소·실행 결과를 남겨. 문서 메뉴, 쿠키 배너, Storybook 외곽에서 나온 값이 섞이면 컴포넌트의 직접 예시나 iframe을 확인해. 추출 누락은 브라우저 계산 스타일로 대조할 수 있지만, 어느 도구로 측정했는지 구분해줘. 접근에 실패하면 실제 실패와 대체 근거를 표시해. 현재 앱의 값은 CSS와 렌더링으로 대조해줘.

5. **측정값을 우리 앱에서 쓸 규칙으로 바꿔줘.** DESIGN.md에는 ‘레퍼런스에서 관찰한 값 → 우리 앱에 채택할 값·용도 → 선택 이유’를 연결해. 한글 지점명과 시각의 크기·굵기·줄높이, 같은 편의 기본/금요일 시각 사이 간격, 서로 다른 편 사이 간격, 배경·본문·강조·주의·키보드 초점 색, 카드 구분과 상세 진입 방식을 포함해. 외국어 폰트의 숫자 크기를 한국어 카드에 적용할 때는 실제 지명 줄바꿈과 대비를 확인해. 기존 앱 값이 더 잘 맞으면 그대로 채택해도 돼.

6. **같은 조건의 전후를 보여줘.** 390px 화정동 서광주우체국 결과를 현재 화면과 제안 시안으로 나란히 보여줘. 송정③ 학교 출발 기본 17:30·금요일 15:30, 송정⑦ 18:20, 학교 승차 MNU 스퀘어 앞을 대조해. ‘약 640m’는 선택한 목적지에서 등교 송정① ‘서광주우체국 건너편 CU편의점’ 표시점까지의 직선거리야. 실제 하차 위치·운행요일의 미확인 상태를 카드에서 읽을 수 있어야 해. 운행편별 상세 진입, 거리순 목록의 더보기, 목록 복귀를 설계에 반영해. 긴 지점명·두 편·요일 예외가 함께 있어도 어느 시각이 어느 편에 속하는지 확인해. 데이터와 한국어 원문을 가능한 한 같게 두고, 문구 수정이 필요하면 별도로 표시해.

최종 보고에는 ① 구조용 두 자료와 비주얼 기준 한 곳의 역할, ② 실제 추출에 성공한 대상과 누락, ③ 전후 시안과 디자인 시스템 경로, ④ 채택을 권하는 규칙과 그 이유를 간결하게 담아줘. 시안으로 확인한 레이아웃과 실제 사용자 평가 결과는 구분해줘.
