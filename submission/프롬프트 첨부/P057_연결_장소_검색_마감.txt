도림통학의 장소 기반 등하교 검색을 이번에 기능적으로 마감해줘. 앱과 필요한 데이터 연결을 직접 수정하고, 실제 검색과 빌드 검증까지 수행해. 그다음 단계는 UI 최종 검토야.

완료 기준은 통학생이 정류장 이름을 몰라도 광주에서 아는 장소 하나를 선택하면, 그 근처를 지나는 것으로 근거를 댈 수 있는 편을 발견하고 어디서 몇 시에 탈지 판단할 수 있는 거야. 정확한 승하차 위치를 모를 때도 주변 시설이나 반대 방향 정류장까지의 대략적인 거리는 유용해. 다만 화면을 읽은 사람이 그 숫자가 어디까지의 거리인지 답할 수 있어야 해.

1. 먼저 지금 빠지는 답을 확인해.
프로젝트 AGENTS.md, DATA_RULES, P055 기능 마감 보고서와 P056 기록을 읽어. 390px에서 하교를 선택하고 서구 화정동의 ‘힐스테이트’ 사례를 재현해. 같은 브랜드의 여러 단지가 나오면 구·동·단지명을 확인해서 선택하고, 정확한 거주지는 묻거나 산출물에 기록하지 마. 재현용 공개 시설도 같은 생활권에서 하나 골라. 공식 노선표(안) S25 p.1에서 서광주우체국은 하교 송정③·⑦, 추선회관은 하교 송정④·⑩이야. 네 편 모두 학교 승차는 MNU 스퀘어 앞(사용자 확인), ③·④는 학교 출발 기본 17:30에 금요일 15:30 대체, ⑦·⑩은 18:20에 기본 운행요일 미표기야. 서광주우체국과 추선회관을 다시 입력하지 않은 상태에서 어떤 답이 나오는지 기록하고 시작해.

2. ‘어떤 편이 지나는가’와 ‘어디에 내리는가’에 각각 맞는 근거를 사용해.
• 편과 경유 순서, 승하차 역할, 시각·요일은 해당 방향 공식 시간표에서 가져와. 등교와 하교에서 겹치는 구간의 앞뒤 지점과 역순은 같은 생활권인지 판단하는 데 활용해. 같은 편 번호나 뒤집은 등교 순서만으로 하교편을 만들지 마.
• 해당 방향 공식 Unibus 표시점이 있으면 그 표시점까지의 직선거리를 써. 지도 표시점의 확인 수준과 기존 진월①의 같은 방향 참고 연결은 유지해.
• 하교 좌표가 없어도, 시간표에 명시된 시설을 광주의 실제 지도 시설과 신뢰성 있게 연결할 수 있으면 그 시설을 기준으로 경유편을 보여줘. 시설 대신 대응하는 등교 정류장만 특정되는 경우에는 그 등교 표시점을 기준으로 삼아도 돼. 시설명·구/동·주소, ‘앞/건너편/정문’ 같은 원문 단서, 양방향 인접 지점, 공공 정류소의 방향·ID 등 해당 사례에 맞는 근거를 적용해. 입력 장소와 이름이 달라도 좌표로 근처를 찾게 해. 동명 시설, 이전한 건물, 서로 다른 단지·출입구가 섞일 때는 자동 연결을 보류해.
• S25에 ‘건너편’이 적혀 있으면 무엇의 건너편인지 원문 그대로 안내해. 예컨대 등교 ‘서광주우체국 건너편 CU편의점’과 하교 ‘서광주우체국’은 같은 시설 주변을 설명하는 단서야. 실제 하차 도로변이나 맞은편 승강장이 별도 자료로 특정될 때만 그쪽 위치를 안내해. 도로 폭을 가정해 좌표를 몇 m 옮기거나 출처 없는 오차 범위를 만들지 마.
• 거리 문구에는 두 끝점을 밝혀. 예를 들면 ‘선택한 장소에서 서광주우체국 건물까지 직선 약 ○○m · 실제 하차 위치 확인 필요’ 또는 ‘선택한 장소에서 등교 정류장 표시점까지 약 ○○m’야. ○○은 확인된 두 좌표에서 계산하고 읽기 쉽게 반올림해. 반경 판정도 그 기준점에 적용해. 기준점의 좌표를 하차 좌표 칸에 넣거나 도보 거리·시간으로 바꾸지 마. 출처·대응 근거를 보존하고 기존 규칙에 이 용도를 명시해.

3. 장소를 선택한 첫 결과에서 편을 찾게 해.
거리 후보가 이미 있어도 주변 시설로 발견한 편이 함께 보여야 해. 먼 공식 표시점 여러 개나 최대 표시 개수 때문에 가까운 시설을 지나는 편이 전부 밀리지 않는지 봐. 시설 기준이라는 짧은 문구를 거리 바로 옆에 두고, 해당 시설을 지나는 편·학교 타는 곳·출발 시각·요일을 같은 결과에서 비교해. 같은 편·같은 하차 지점에 여러 근거가 있으면 중복 노출하지 말고 가장 직접적인 근거를 먼저 써. 자동 발견이 어려운 곳에는 부족한 정보를 밝히고 기존 시간표 검색·조건 변경을 이어줘.

등교에도 같은 원칙을 쓰되, 시각은 선택한 광주 지점의 승차 시각을 써. 하교에서는 학교 출발과 광주 하차 도착시각 미제공을 구별해. 금요일 대체·시간 경계, 기본 요일 미확인, 특정 요일만 경유, 자료 충돌의 보류 범위를 모든 후보에 동일하게 적용해. 지도·상세·복귀 화면에서도 사용자가 선택한 지점과 거리의 기준이 바뀌지 않아야 해.

4. 두 정류장 패치로 끝내지 말고 광주권 전체에서 검증해.
양방향 38편의 승하차 관계 전체를 살펴보고, 확보한 자료로 연결 가능한 시설·대응 정류장을 일반적인 방식으로 처리해. 아파트 이름과 노선 번호를 특별히 짝짓지 마. 광주 어디서 검색하든 근거 있는 후보나 그 지역에서 비교할 수 없는 이유를 얻도록 해. 기존 데이터와 공개 자료를 우선하고, 검색 때마다 모든 정류장을 외부 API로 조회하지 않도록 구현해. 시설 좌표를 미리 수록할 때는 출처와 저장·재사용 조건이 확인된 자료를 써. 장소 검색이나 지도 서비스가 일시적으로 실패해도 수록 시간표와 텍스트 안내는 계속 이용할 수 있어야 해.
• 화정동 실제 선택 장소에서 기본 3km·시각 전체로 시작해 두 기준점의 실제 계산값을 확인해. 반경에 든다면 정류장 재입력 없이 서광주우체국 송정③·⑦과 추선회관 송정④·⑩을 발견해야 해. 금요일 16:00 이후에는 ③·④의 15:30이 시간 조건을 통과하지 않고, ⑦·⑩은 18:20과 기본 요일 미확인을 함께 표시해야 해. 반경 밖이라면 계산 근거와 반경 변경 결과를 남겨. 사례를 맞추려고 반경이나 좌표를 바꾸지 마.
• 구현 전에 다른 생활권에서도 공개 시설 입력을 골라 둬. 광산구나 북구의 장소에서 같은 방법이 통하는지, 하교표에 없는 등교 전용 지점과 다른 동의 동명 시설이 섞이지 않는지, 가까운 근거가 없는 곳에서 무관한 편을 밀어 넣지 않는지 확인해. 공식 하교 표시점이 있는 지점 하나는 그 표시점을 잠시 가린 검증 입력으로 사용해. 추론이 같은 시설을 가리키는지 확인하고 실제로 관찰한 차이만 기록해.
• 문흥동 샛터코아 금요일 16:00 이후를 다시 확인해. 새로운 기준점으로 진월⑤를 발견했다면 학교 18:20·기본 운행요일 미확인·위치 근거가 함께 보여야 해. 기존 거리 결과 0개를 새 방식의 정답으로 고정하지 마. 등교 중간 정류장, 요일 불일치, 한 편의 지점 둘이 일치하는 검색, 상세 새로고침과 뒤로 가기도 회귀 확인해.

5. 자료가 얼마나 나아졌는지와 기능 마감 여부를 보고해.
기존 하교 19편·175개 하차 관계 중 거리 비교 3편·34관계의 내역은 해당 편 직접 표시점 2편·24관계와 같은 방향 참고 연결 1편·10관계야. 현재 데이터로 이 수를 재확인하고, 새로 시설 또는 등교 표시점으로 발견할 수 있게 된 고유 편·관계 수, 여전히 위치 근거가 없는 관계 수, 대표 검색 조건에서 실제 표시된 편 수를 따로 집계해. 같은 관계에 근거가 겹치면 한 번만 세고, 위치 근거가 있어도 충돌·조건으로 보류한 항목은 이유를 밝혀.

390px 모바일과 데스크톱에서 장소 입력→자동 발견→편 비교→상세→복귀를 수행해. 실제 Kakao·공식 Unibus 관찰과 통제한 응답 검사를 표시하고, 타입·빌드·기본 제한의 관련 회귀와 프로덕션 핵심 흐름을 검증해. 공개 시설의 대표 결과와 상세 캡처를 남겨. 실제 사용자 평가나 당일 운행 확인으로 보고하지 마.

최종 답변 첫 줄에 ‘기능 마감 가능’ 또는 ‘기능 마감 보류’와 이유를 써. 시험한 장소, 자동으로 발견된 편, 거리의 양 끝점, 남은 학교 확인 사항을 근거와 함께 보여줘. 정류장명을 이미 아는 사람만 두 하차지를 찾을 수 있거나, 참고 거리를 실제 하차 거리로 오인하게 하는 문제가 남으면 보류야. 자료로 특정할 수 없는 현장 위치는 그 한계를 정확히 안내하면 마감할 수 있어. 마지막에는 사람이 UI 최종 검토에서 해 볼 과업 세 개만 남겨.
