# 도림통학

광주권에서 도림캠퍼스로 통학하는 학생은 갈 곳을 알아도 학교 노선표에 적힌 정류장 이름까지 알기는 어렵다. 도림통학은 학생이 아는 아파트·건물·장소에서 출발해 이용할 수 있는 통학편을 살펴보는 웹 프로토타입이다.

## 직접 써 보면서 시작한 아이디어

집 주변은 지리를 대충 알아서 학교 노선표와 카카오맵을 번갈아 보면서 어느 정류장이 가까운지 찾을 수 있었다. 그래도 정류장 이름을 하나씩 검색하는 데 시간이 좀 걸렸다. 낯선 곳에 갈 때는 학교 노선표 PDF를 ChatGPT에 넣고 목적지를 말해 봤다. 바코드커피에 갈 때는 탈 편을 물은 뒤 도보시간을 다시 물었고, 운암동 은행을 찾을 때는 안내받은 ‘운암주공 3단지’가 카카오맵에서 검색되지 않았다.

자료를 챙겨 넣고 질문을 반복한 다음 지도를 다시 확인하는 과정이 생각보다 오래 걸리고 복잡했다. 그래서 도림통학에서는 학교 시간표를 미리 연결해 두고, 학생이 아는 아파트나 건물 이름만으로 탈 편과 내릴 지점을 찾아볼 수 있게 했다. [카페에 가려고 시간표를 넣은 대화](<./개발 프롬프트 기록.html#J01>) · [운암동 은행을 찾은 대화](<./개발 프롬프트 기록.html#C040>)

## 주요 기능

- 등교할 때는 광주에서 탈 지점과 해당 지점의 승차 시각을 확인한다. 하교할 때는 목적지 주변 하차 후보와 그곳을 지나는 편의 학교 승차 위치·출발 시각을 함께 본다.
- 광주권 등교 19편과 하교 19편을 노선명이나 정류장명으로도 찾을 수 있다. 장소 검색 결과가 없거나 거리 비교가 어려운 지점도 시간표에서 확인할 수 있다.
- 금요일 화정동 유니버시아드 힐스테이트 2단지 사례로 공식 Unibus·학교 노선표를 이용하는 방법과 목적지 이름으로 찾는 방법을 비교한다. 지도에 다른 편의 표시점을 활용한 경우에는 거리를 잰 기준점을 밝힌다.

## 작업 지시를 정리한 방법

기획 단계에서는 ChatGPT와 통학 경험을 이야기하고 첫 구현에 쓸 프롬프트를 정리했다. 화면을 많이 바꿀 때는 내가 원하는 모습과 불편한 점을 먼저 적고, AI에 그 내용을 실행 순서와 확인 조건이 있는 프롬프트로 정리해 달라고 했다. 초안을 읽어 보고 집계 문구는 줄이되 실제 도로변 안내는 남기자고 했고, 정원 그린을 적용할 때는 초록 일색이 되지 않도록 식물원의 색을 더 찾아 달라고 했다. 수정한 문안으로 구현을 요청한 뒤에는 같은 화정동 하교 화면을 390px에서 전후로 비교하도록 했다. [초안에 빼고 더한 조건](<개발 프롬프트 기록.html#method>)

## 디자인을 정하고 문구를 검수한 과정

1. **통학 화면에 맞는 레퍼런스 찾기.** Awwwards를 예로 들며 레퍼런스를 살펴보는 데서 시작했다. 화정동 하교 결과를 놓고 GOV.UK의 요약 목록에서는 한 지점에 딸린 정보를 묶는 방식을, 스위스 철도 SBB의 정차 순서에서는 학교에서 타고 광주에서 내리는 흐름을 보여 주는 방식을 참고했다. [처음 정한 디자인 작업 순서](<./개발 프롬프트 기록.html#P081>) · [레퍼런스 비교](<./개발 프롬프트 기록.html#P082>)

2. **디자인 시스템으로 화면 만들기.** Dembrandt로 참고 사이트의 색·글자 크기·간격을 추출한 뒤, 우리 화면에서 어떤 역할로 쓸지 정했다. 화면을 하나 더 만들 때마다 AI가 같은 선택을 다시 하지 않게 하려는 생각이었다. 정원 그린의 진초록은 검색 버튼과 선택한 편에, 갈색은 실제 하차 위치를 확인해야 하는 안내에 썼다. 모바일 카드 안쪽 여백은 16px로 맞추고 편명과 학교 출발 시각을 같은 줄에 뒀다. [디자인 토큰 추출](<./개발 프롬프트 기록.html#P087>) · [식물원 색 보완](<./개발 프롬프트 기록.html#P097>) · [390px 전후 비교](<./개발 프롬프트 기록.html#P098>)

3. **ChatGPT로 한국어 문구 검수하기.** 화면 배치를 정한 뒤 화정동 하교 결과와 상세 화면의 한글 문구를 뽑아 ChatGPT와 검토했다. 송정③이 금요일에는 17:30 대신 15:30에 출발한다는 점, 약 640m는 검색한 단지에서 등교편의 지도 표시점까지 잰 직선거리라는 점이 처음 타는 학생에게도 읽히는지 물었다. 두 수정안을 비교해 앱에 반영하고, 요일을 고르기 전과 금요일을 고른 뒤 화면을 다시 확인했다. [학생 입장에서 읽어 본 질문](<./개발 프롬프트 기록.html#C058>) · [문구 적용 후 확인](<./개발 프롬프트 기록.html#P112>)

## 직접 시연해 발견하고 고친 점

- **화정동 하교 후보.** 집 주변으로 검색했더니 등교 결과는 아는 노선과 맞았지만 하교에서는 서광주우체국과 추선회관이 빠졌다. 두 곳을 직접 지목해 이유를 물었고, 시간표에는 있는 편이 하차 좌표 부족으로 거리 비교에서 빠지는 것을 확인했다. 이후 참고할 지도점까지의 직선거리와 실제 하차 위치 확인 여부를 나누어, 두 지점을 지나는 편도 비교할 수 있게 했다. [누락 제보](<./개발 프롬프트 기록.html#P056>) · [개선 기록](<./개발 프롬프트 기록.html#P058>)

- **단지 검색과 더보기.** ‘힐스테이트’와 ‘힐스테이트 2단지’를 각각 입력한 결과를 보고, 단지와 부속시설이 섞이고 더보기를 눌러도 세 곳씩만 열리는 점을 짚었다. 구와 장소 종류로 결과를 좁히고, 남은 장소는 한 번에 펼칠 수 있게 했다. [검색 화면 제보](<./개발 프롬프트 기록.html#P102>) · [더보기 개선](<./개발 프롬프트 기록.html#P104>)

- **홈과 검색 결과.** 로고를 눌러도 이전 검색 조건이 남았고, 새 장소를 검색한 뒤에는 결과가 화면 아래에 있어 직접 스크롤해야 했다. 로고는 빈 검색 화면을 열고, 검색이 끝나면 결과 목록으로 화면과 키보드 초점이 이동하도록 고쳤다. [홈 재현](<./개발 프롬프트 기록.html#P126>) · [검색 직후 시연](<./개발 프롬프트 기록.html#P129>)

- **상세 지도와 뒤로가기.** 1번 기준점을 눌러 보니 상세 지도에 내가 검색한 장소가 보이지 않았다. 뒤로가기를 누르면 보고 있던 화면보다 한 단계 더 뒤로 갔다. 캡처와 누른 순서를 함께 전달했고, 상세 지도에 목적지 핀을 표시하고 직전 화면으로 돌아가도록 수정했다. [지도 캡처와 재현 순서](<./개발 프롬프트 기록.html#P130>)

## 실행 검증

AI 점검에는 정류장 이름을 모르는 신입생, 이동 중 큰 시각부터 보는 통학생, 준비한 장소 밖의 사례를 요구하는 시연 심사자 같은 역할을 지정했다. 실제 사람 평가 범위는 작성자 한 명으로 계획했다. 각 역할의 행동 조건과 직접 시연 기록을 함께 남겼다. [가상 역할별 과업](<개발 프롬프트 기록.html#personas>)

최종 로컬 빌드에서 단위·UI 검사 136건, 개발 브라우저 검사 66건, 빌드본 브라우저 검사 36건을 통과했다. 실제 장소 검색으로 서광주우체국 후보에서 송정③의 금요일 학교 출발 15:30과 MNU 스퀘어 앞 승차 안내를 확인했다. 이 검사는 기능 동작을 확인한 것이며 통학생의 탐색 시간 단축 효과는 측정하지 않았다.

과제 제출을 준비하면서 MVP라는 말이 우리 앱의 어느 단계에 해당했는지, 하교 후보와 지도의 뒤로가기는 왜 예상과 다르게 동작했는지 당시 기록으로 다시 살펴봤다. [완성 후 회고](<개발 프롬프트 기록.html#reflection>)
