전달한 실행 계획의 발췌입니다. 개인 파일 경로, 실행 환경 추천과 이전 계획 단계의 끝 안내는 생략했습니다.
당시에는 별도 비교안으로 요청했으며, 이후 기본 화면과 공개 사이트에 적용했습니다.

# 도림통학 상단 구조·한국어 문체 개선 계획

## 1. 목표와 적용 기준

상단은 ‘중앙 서비스명·아래 메뉴’로 바꾸고, 한국어는 대학의 이용 안내에 어울리는 간결한 합니다체로 정리합니다. 정원 그린 색감과 그림, 현재의 검색·목록 이용 방식은 유지합니다.

한국어 참고 자료는 다음처럼 역할을 나누어 사용합니다.

- [국립목포대학교 통학버스 안내](https://www.mokpo.ac.kr/www/276/subview.do): 기능과 대상을 직접 밝히는 제목을 참고합니다.
- [경기버스정보 검색 화면](https://m.gbis.go.kr/search): ‘최근 검색’ 같은 짧은 제목과 ‘최근 검색이 없습니다.’ 같은 상태 안내를 참고합니다.
- [KRDS 검색어 입력 지침](https://www.krds.go.kr/html/site/service/service_02_03.html): 무엇을 검색하는지 입력란 이름에 명시하고, 필수 설명을 입력하면 사라지는 안내문에만 두지 않는 원칙을 적용합니다.

적용 대상은 홈·장소 검색·후보 결과·노선 목록·상세·이용 안내입니다. 공식 사이트에 어울리는 문체를 사용하되, 학생 프로젝트와 비공식 서비스라는 표시는 유지합니다.

기본 화면을 보존하고, 기존 `?ui=refined`를 이번 비교안으로 갱신합니다. 이전 실험의 캡처와 검토 기록은 보관합니다.

## 2. 상단 구성과 기존 실험의 선별 적용

[Financial Times](https://www.ft.com/)의 중앙 제호와 그 아래 메뉴 배치를 참고해, 현재 왼쪽에 붙어 있는 학교 심볼과 ‘도림통학’을 함께 중앙으로 옮깁니다.

| 위치 | 구성 |
|---|---|
| 첫째 줄 왼쪽 | 작은 ‘학생 프로젝트’ 표시 |
| 첫째 줄 가운데 | 기존 학교 심볼 + 도림통학 |
| 첫째 줄 오른쪽 | 공식 Unibus 외부 링크 |
| 둘째 줄 가운데 | 홈 · 노선 목록 · 이용 안내 |

- 가운데 묶음은 화면의 실제 중앙에 맞춥니다. 좌우 내용의 길이가 달라도 밀리지 않게 합니다.
- 모바일에서도 같은 구조를 사용합니다. 메뉴 세 개를 모두 표시하고, 필요한 보조 문구는 줄바꿈합니다.
- 서비스명은 기존 글꼴을 사용하되 데스크톱 26px, 모바일 20px·굵기 700으로 정리합니다. 심볼의 비율과 색은 보존합니다.
- 기본 글자 크기에서 상단 높이는 112px 이내를 목표로 합니다. 글자를 확대하면 내용에 맞춰 높이가 늘어나게 합니다.
- 중앙 서비스명을 누르는 홈 이동, 현재 메뉴 표시, 키보드 초점은 기존 동작을 유지합니다.

이전 개선안에서는 장소명/주소 선택지를 하나의 선택 영역으로 묶는 표현, 지도 버튼의 선택 전후 동일한 안쪽 여백만 이어받습니다. 검색 버튼 100px 고정, 카드의 미세한 간격·모서리 변경, 펼침 아이콘 회전은 이번 안에서 제외합니다.

## 3. 한국어 문체 명세

### 문장의 역할에 따라 형태를 고정합니다

| 역할 | 작성 규칙 | 사용할 표현 |
|---|---|---|
| 화면·영역 제목 | 내용을 바로 나타내는 명사형 | 노선 목록 / 검색 조건 / 학교 승차 위치 |
| 버튼·링크 | 누른 뒤 일어나는 동작 표시 | 장소 검색 / 지도 보기 / 시간 조건 해제 |
| 사실·기능 설명 | `~입니다`, `~합니다`, `~할 수 있습니다` | 하교 시각은 학교 출발 시각입니다. |
| 상태·결과 안내 | 현재 상태를 먼저 제시 | 검색 결과가 없습니다. |
| 사용자에게 필요한 요청 | 짧은 `~해 주세요` | 장소명이나 주소를 확인해 주세요. |
| 자료의 한계 | 확인하지 못한 대상을 구체적으로 표시 | 실제 하차 위치는 확인되지 않았습니다. |

설명문에서 `~있어요`, `~없어요`, `~했어요`는 사용하지 않습니다. 요청에는 대학 사이트에서도 사용하는 ‘입력해 주세요’ 형태를 사용합니다. 모든 문장을 ‘주시기 바랍니다’로 늘리지 않습니다.

추가 작성 규칙은 다음과 같습니다.

- ‘나의·익숙한·편리한·빠르게·바로’는 기능상 의미가 있을 때만 사용합니다. 사용자에게 익숙한지, 개인화한 결과인지, 실제로 빨라지는지 확인되지 않았다면 넣지 않습니다.
- 제목·버튼·짧은 항목명에는 마침표를 붙이지 않고, 완결된 설명문에는 붙입니다.
- 한 문장에는 사실 하나를 담습니다. 조건이나 예외가 필요하면 다음 문장으로 분리합니다.
- ‘검색’, ‘보기’, ‘선택’, ‘해제’를 임의로 섞지 않습니다. 검색은 검색 실행, 보기는 화면 이동·내용 표시, 선택은 대상 지정, 해제는 적용된 조건 제거에 사용합니다.
- ‘죄송합니다’, ‘잠시만 기다려 주세요’, ‘다시 한번 확인해 보세요’만으로 상태 안내를 끝내지 않습니다. 발생한 상황과 가능한 다음 동작을 적습니다.
- 공식 지명·정류장명·편명·원문 인용은 문체 통일 대상으로 바꾸지 않습니다.

### 주요 문구는 아래 내용으로 교체합니다

| 위치 | 현재 표현 | 적용할 표현 |
|---|---|---|
| 홈 제목 | 아는 장소로 찾는 나의 통학편. | 장소로 통학버스 찾기 |
| 홈 설명·등교 | 아파트·건물 이름으로 가까운 정류장과 시각을 확인하세요. | 출발지 주변 승차 정류장과 정류장별 승차 시각을 확인합니다. |
| 홈 설명·하교 | 위와 동일 | 목적지 주변 하차 정류장과 학교 출발 시각을 확인합니다. |
| 홈 노선 영역 제목 | 익숙한 노선, 바로 확인하기 | 등교·하교 노선 |
| 홈 노선 영역 설명 | 장소 검색 없이도 운행편과 정류장을 살펴볼 수 있어요. | 방향을 선택하면 운행편과 정류장을 확인할 수 있습니다. |
| 등교 검색 입력란 | 어디에서 출발하시나요? | 출발지 장소명 / 주소 모드에서는 출발지 주소 |
| 하교 검색 입력란 | 어디로 돌아가시나요? | 목적지 장소명 / 주소 모드에서는 목적지 주소 |
| 검색 실행 | 주소 모드에서도 장소 검색 | 장소 검색 / 주소 검색 |
| 노선 목록 검색란 | 수록 노선·정류장 이름 | 노선명 또는 정류장명 |
| 등교 결과 제목 | 주변 승차 지점·시각 | 승차 정류장 후보 |
| 하교 결과 제목 | 목적지 주변 하차 후보 | 하차 정류장 후보 |
| 노선 목록으로 이동하는 링크 | 전체 시간표 보기 | 등교 노선 전체 보기 / 하교 노선 전체 보기 |
| 시간 조건까지 해제하는 링크 | 시간 조건을 풀고 … 전체 시간표 보기 | 시간 조건 해제 후 등교 노선 전체 보기 / 하교 노선 전체 보기 |
| 이용 안내의 목록 이동 버튼 | 노선 살펴보기 | 노선 목록 보기 |
| 하단 소개 | 나의 일상과 학교를 잇는 통학 정보 | 광주권 ↔ 도림캠퍼스 통학버스 안내 |

‘홈’, ‘노선 목록’, ‘이용 안내’, ‘학교 승차 위치’처럼 이미 정확한 표현은 유지합니다.

홈 설명은 선택한 등교·하교 방향에 따라 바꿉니다. 특히 하교에서 제공하는 시각을 목적지 도착 시각으로 오해하지 않게 합니다.

### 검색·오류·빈 결과의 문구를 구분합니다

| 실제 상태 | 표시 문구와 후속 안내 |
|---|---|
| 장소 검색 중 | 버튼: `검색 중…` / 상태 알림: `장소를 검색하고 있습니다.` |
| 주소 검색 중 | 버튼: `검색 중…` / 상태 알림: `주소를 검색하고 있습니다.` |
| 검색 호출 실패 | `검색 결과를 불러오지 못했습니다.` + 기존 다시 검색·노선 목록 경로 제공 |
| 검색어에 해당하는 장소 없음 | `‘{검색어}’에 대한 장소 검색 결과가 없습니다.` + `장소명이나 주소를 확인해 주세요.` |
| 지역·종류 필터로 장소가 모두 제외됨 | `선택한 지역·종류에 맞는 장소가 없습니다.` + 해당 필터 변경 안내 |
| 장소 선택 후 거리 비교 결과 없음 | `현재 조건에 맞는 거리 비교 결과가 없습니다.` + 적용 중인 요일·시간·거리 조건에 맞는 복구 동작 제공 |
| 거리 비교 지원 지역 밖 | `선택한 장소는 거리 비교 지원 지역 밖입니다.` + 장소 재선택·노선 목록 경로 제공 |
| 주말 조건 | `주말에는 정규 통학버스가 운행하지 않습니다.` + `이용 요일을 평일로 변경해 주세요.` |
| 위치 자료가 없어 거리 결과에 포함되지 않음 | `위치 자료가 없는 운행편은 노선 목록에서 확인할 수 있습니다.` |
| 지도에 표시할 좌표 없음 | `지도에 표시할 위치 좌표가 없습니다.` + 기존 위치 설명 유지 |
| 실제 승하차 위치 미확인 | `실제 승차 위치는 확인되지 않았습니다.` / `실제 하차 위치는 확인되지 않았습니다.` |
| 존재하지 않는 운행편 상세 주소 | `해당 운행편을 찾을 수 없습니다.` + `노선 목록에서 운행편을 선택해 주세요.` |
| 시간표 변경 가능 안내 | `공식 노선표(안) 기준이며, 변경될 수 있습니다.` |

검색 실패의 원인이 확인되지 않았다면 ‘인터넷 연결 문제’라고 추정하지 않습니다. 설정·권한 등 이미 구분되는 오류는 그 의미를 유지합니다.

복구 안내는 실제 제공되는 조작과 맞춥니다. 이미 최대 반경인 상태에서 반경 확대를 안내하거나, 시간 조건이 없는 상태에서 시간 조건 해제를 권하지 않습니다.

### 용어와 정보의 의미를 고정합니다

| 용어 | 사용할 의미 |
|---|---|
| 장소 | 사용자가 검색·선택한 아파트, 건물, 주소 |
| 정류장 | 시간표에 수록된 승하차 지점 |
| 운행편 | 편명과 시각으로 구분되는 개별 운행. 개수는 ‘편’ |
| 노선 목록 | 운행편을 탐색하는 현재 목록 화면 |
| 거리 기준점 | 직선거리를 계산한 지도 표시점 또는 주변 시설 |
| 승차 시각 | 등교 시 선택한 정류장에서 승차하는 시각 |
| 학교 출발 시각 | 하교 시 도림캠퍼스에서 출발하는 시각 |

‘자료 없음’, ‘확인되지 않음’, ‘운행하지 않음’도 구별합니다. 자료가 없다는 이유로 버스가 운행하지 않는다고 표현하지 않습니다.

거리 기준점이 실제 승하차 위치와 다를 수 있다는 설명, 금요일 변경, 학교 승차 위치, 원문의 ‘(안)’ 표시는 유지합니다. ‘직선거리’를 ‘도보거리’로 바꾸거나 후보를 ‘추천 노선’으로 확정하지 않습니다.

표에 없는 문구는 기존 사실을 유지하면서 위의 종결어미·용어·동작명 규칙만 적용합니다. 새로운 슬로건이나 홍보성 설명은 추가하지 않습니다.

## 4. 구현 방식과 변경 경계

- 기존 컴포넌트와 검색 상태를 공유하고, 실험 여부에 따라 표시 문구와 상단 스타일만 선택합니다. 화면 전체를 복제하지 않습니다.
- 변경 문구는 작은 표시용 문구 모음으로 관리합니다. 등교·하교, 장소·주소, 검색 상태에 필요한 문장은 해당 상태값으로 선택합니다.
- 데이터에서 전달되는 제외 사유는 기존 사유 코드에 맞춰 표시 문구만 정리합니다. 검색·정렬·거리 계산과 제외 조건은 변경하지 않습니다.
- `?ui=refined` 적용 범위에 이용 안내를 포함합니다. `#/compare`, `#/asis`, `#/evaluation` 및 과제용 비교·평가 도구의 문구와 스타일은 보존합니다.
- 홈 이동·상세 왕복·새로고침 시 실험 모드를 유지합니다. 기존 시연 종료와 검색 초기화 동작도 유지합니다.
- 공개 API, 운행 데이터 타입, 외부 검색 요청 형식은 변경하지 않습니다.
- 작업은 원래 프로젝트의 `app/`과 기존 설계·검토 기록에 한정합니다. 공개 사이트, 저장소 복사본, 제출 ZIP은 갱신하지 않습니다.
- 실행 시 문구별 `화면·상태 / 기존 표현 / 변경 표현 / 변경 이유`를 기존 검토 기록에 남기고, 이번 요청과 선택도 기존 프롬프트 기록 방식으로 보존합니다.

## 5. 검증과 완료 기준

문구 검증

- 등교·하교와 장소·주소의 네 조합에서 제목·입력란·버튼·검색 중 알림이 일치하는지 확인합니다.
- 장소 검색 0건, 필터 결과 0건, 거리 비교 0건, 검색 실패, 위치 미확인을 각각 확인합니다.
- 하교 시각을 도착 시각으로 읽게 하는 표현, 자료 누락을 미운행으로 단정하는 표현이 없는지 확인합니다.
- 버튼·링크의 이름과 실제 이동·조건 해제 동작을 대조합니다.
- 일반 화면의 설명문에서 해요체 혼용과 불필요한 홍보 문구를 확인하되, 공식 원문과 지명은 검사 대상에서 구분합니다.

화면·기능 검증

- 320·390·768·1440px에서 중앙 정렬, 메뉴 노출, 긴 한국어 줄바꿈, 가로 넘침을 확인합니다.
- 390px에서 검색 입력란의 폭과 첫 후보 카드의 두 편 시각이 기존보다 불리해지지 않는지 비교합니다.
- 글자 확대, 키보드 이동, 현재 메뉴 표시, 지도 선택, 상세 복귀, 뒤로·앞으로 이동을 확인합니다.
- 기본 화면과 비교·평가 화면에 문구·스타일 변경이 새어 들어가지 않는지 확인합니다.
- 타입검사·전체 단위/UI 검사·빌드와 기존 개발·프로덕션 브라우저 검사를 실행합니다. 문구 변경에 따른 기존 검사 수정은 실제 기능 의미를 유지합니다.

완료 결과는 기본안·새 비교안 로컬 링크, 같은 조건의 전후 캡처, 문구 변경표, 채택·보류 판단으로 제공합니다. 문체의 일관성과 화면 동작 검증을 실제 통학생의 사용성 향상으로 보고하지 않습니다.
