전달한 실행 계획의 발췌입니다. 개인 파일 경로, 실행 환경 추천과 이전 계획 단계의 끝 안내는 생략했습니다.
당시에는 별도 비교안으로 요청했으며, 이후 기본 화면과 공개 사이트에 적용했습니다.

# 정원 그린 UI 유지·개선 실험 계획

## 1. 목표와 결과물

현재 디자인의 색감과 정보 배치를 유지하면서, MotionSites와 Stageshow에서 가져온 요소가 실제 사용 화면을 더 정돈해 주는지 비교한다.

- 기존 화면은 기본값으로 보존한다.
- 개선안 하나를 별도 로컬 주소 `/?ui=refined`에서 제공한다.
- 두 화면은 동일한 실제 데이터·검색·지도·상세 기능을 사용한다.
- 대상은 홈, 장소 검색, 후보 결과, 노선 목록, 상세 화면이다. 별도 소개 애니메이션은 만들지 않는다.
- 공개 사이트와 제출본은 갱신하지 않는다. 이번 작업의 완료 결과는 작동하는 비교안과 전후 검토 자료다.

## 2. 두 도구의 활용 방식

### MotionSites: 시각 요소를 선별하는 레퍼런스

직접 확인한 [Smart Home 공개 예시](https://motionsites.ai/?prompt=smart-home)의 선택 탭과 관련 기능을 묶는 방식을 참고한다. 이를 현재 방향 선택·검색 조건·결과 카드에 맞춰 재해석한다.

무료 공개 미리보기를 기본 자료로 사용하므로 가입·결제·MCP 연결을 작업의 선행조건으로 두지 않는다. ‘Copy prompt’의 완료 안내는 확인했으나 본문은 확보하지 못했으므로, 프롬프트를 읽거나 적용했다고 기록하지 않는다.

### Stageshow: 시각적 위계와 움직임 검수

[Stageshow 원문](https://raw.githubusercontent.com/benjitaylor/skills/main/stageshow/SKILL.md)의 `craft`, `motion`, `rehearse` 지침에서 일반 UI에 적용 가능한 부분을 사용한다.

- 먼저 정지 화면의 정렬·간격·강조를 정리한다.
- 움직임은 사용자의 입력과 상태 변화를 설명하는 데 사용한다.
- 완료 화면뿐 아니라 전환 중간과 연속 조작도 확인한다.

연출용 글자 생략·가짜 커서·화면 자르기 규칙은 실제 이용 화면에 적용하지 않는다. 전용 React 키트 대신 기존 React·CSS로 구현하고, 현재 프로젝트의 브라우저 검사 도구로 검수한다.

## 3. 구현할 변경

### 현재 디자인의 정돈

현재 디자인 시스템을 기준으로 정원 그린, 따뜻한 바탕, 풀·꽃 그림, 공식 심볼과 글꼴을 유지한다.

| 영역 | 개선안 |
|---|---|
| 홈·검색 조건 | 방향 선택, 장소명/주소 선택, 검색 버튼의 선택·누름·비활성 상태를 같은 규칙으로 정리한다. 조작 영역은 최소 44px을 확보한다. |
| 선택한 장소 머리말 | 긴 한글 장소명의 줄바꿈을 균형 있게 조절한다. 이름 전체와 주소를 유지하고 그림 영역과 겹치지 않게 한다. |
| 후보 카드 | 지점·거리 설명, 편명·시각, 지도·출처의 세 묶음 사이 간격을 정돈한다. 지점명 21px·시각 22px과 편별 행 구조를 유지한다. |
| 목록·상세 | 같은 종류의 링크·선택 테두리·보조 설명에 동일한 표현을 적용한다. 학교 승차 위치와 출발 시각, 선택한 승하차 지점의 관계를 유지한다. |

간격은 4·8·12·16·24px 단위로 정리하되, 긴 문구에 맞춰 높이가 늘어나도록 한다. 정보 삭제나 새로운 펼침 안으로의 이동은 하지 않는다.

### 짧고 일관된 피드백

- 버튼과 선택 탭의 색·테두리 변화: 120ms.
- 지도와 연결된 후보 카드 강조: 160ms. 강조가 끝나도 선택 표시는 남긴다.
- 펼침 표시 아이콘의 회전: 160ms. 본문의 높이와 페이지 스크롤은 애니메이션으로 제어하지 않는다.
- 검색 중에도 버튼 폭을 유지해 주변 요소가 흔들리지 않게 한다.
- `prefers-reduced-motion`에서는 전환을 끄고 최종 상태를 즉시 표시한다.
- 결과 표시나 초점 이동을 애니메이션 완료까지 기다리게 하지 않는다.

### 비교 구현과 인터페이스

- `ui=refined`일 때만 일반 이용 화면의 루트에 실험 클래스를 추가하고, 별도 CSS로 변경을 한정한다.
- 기존 컴포넌트와 상태를 공유한다. 화면 전체를 복제하거나 두 UI를 동시에 마운트하지 않는다.
- 홈 이동·상세 왕복·새로고침에서도 실험 모드를 유지한다. 기존 시연 종료와 검색 초기화 동작은 보존한다.
- `#/compare`, `#/asis`, `#/evaluation`에는 실험 스타일을 적용하지 않는다.
- 외부 API, 운행 데이터 타입, 검색·정렬·거리 계산 규칙은 변경하지 않는다.
- 작업 대상은 원래 작업 폴더의 `app/`이다. 공개 저장소 복사본과 제출 ZIP은 그대로 둔다.

## 4. 검증과 채택 판단

먼저 현재 파일의 해시와 대표 화면을 보관하고, 같은 조건에서 기존안과 개선안을 촬영한다.

- 화정동 2단지 하교: 송정③·⑦의 시각 비교, 금요일 변경, 학교 승차 위치, 거리 기준과 실제 하차 위치의 구분.
- 등교: 장소 선택 후 지점 승차 시각 확인, 상세 진입과 복귀.
- 예외: 검색 중·검색 실패·결과 0건·조건 변경·전체 노선 목록 복구.
- 상호작용: 지도 선택, 더보기, 출처 펼침, 키보드 초점, 브라우저 뒤로/앞으로, 빠른 연속 조작.
- 화면: 320·390·768·1440px에서 잘림과 가로 넘침 확인. 390px에서는 첫 카드의 두 편 시각이 기존보다 아래로 밀리지 않는지 비교한다.
- 회귀: 타입검사·전체 단위/UI 검사·빌드와 관련 브라우저/프로덕션 검사를 실행한다. 기본 화면과 비교·평가 화면의 스타일 누출도 확인한다.

최종 결과는 두 로컬 링크, 동일 조건 전후 캡처, 짧은 동작 녹화, 변경별 채택 판단으로 제공한다. 새 도구를 사용했다는 이유로 모든 변경을 채택하지 않으며, 정보 읽기나 조작을 방해하는 변경은 실험안에서 제외한다.

실행 시 실제 요청과 선택, 참조 자료, 검증 결과를 기존 기록 방식에 남긴다. 자동 검증과 시각적 판단을 실제 통학생의 사용성 향상으로 보고하지 않는다.
